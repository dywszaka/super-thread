# SuperThread UI 复核与改进方案

日期：2026-11-11。审查基线：`ae1a85d`。状态：方案，尚未实施。

建议沿用当前 macOS 工作台的系统字体、中性灰浅深色和紧凑 Workspace chrome，优先修复失败状态与文档布局，再改善操作层级和控件辨识度。整体换主题对这些问题帮助有限。

## 1. 复核依据与结论

本轮按 Hallmark 的 app scope 复核源码、上一轮原生截图及自动渲染报告，并对初次加载失败补做真实 Electron 故障注入。代码基线未变化，因此没有重复运行同一套完整渲染。计划中的尺寸与断点是设计目标，实施后仍需实测验收。

已有证据覆盖线程列表、文档抽屉、Workspace 概览、Projects、Settings、无终端状态；自动渲染覆盖其中四类界面的浅深色，生成 40 张截图。新故障注入只作用于隔离测试进程，不读取或修改真实用户数据。

| 编号 | 优先级 | 复核结论 | 证据与定位 |
| --- | --- | --- | --- |
| R1 | P1 | 首次读取失败后无法退出启动动画 | 注入 `app:snapshot` 失败，4 秒后已尝试 2 次，仍为 `boot=true / error=false / buttons=[]`；`WorkspaceApp.tsx:77` 在检查错误之前返回 loading |
| R2 | P1 | 文档抽屉挤压列表，窄窗口失去扫描效率 | 880×560、240px 侧栏下，列表约 256px，卡片约 200px 高，删除按钮单独换行；`globals.css:3426` 的宽度分配与 `:3482` 的换行规则共同造成 |
| R3 | P2 | 线程列表的入口语义和视觉权重不一致 | 卡片和 Doc 均打开文档；窗口图标有终端时打开首个终端，无终端时打开文档；Archive 始终为带文字按钮；`WorkThreadList.tsx:103`、`:151`、`:156` |

### 对上一轮建议的校正

- 将窗口图标统一改名为“打开工作区”并不准确：当前 handler 的真实目标是终端或文档。方案按实际目标提供名称，避免只改文案却改变用户预期。
- 正常线程年龄仍需在 Doc 中可获取；提醒与强提醒继续可见。通过合并布局减少高度，不删除产品要求的提醒语义。
- Settings 在最小窗口内采用正文滚动、固定头尾，属于正确行为；不把首屏未展示所有表单字段判成裁切故障。
- `45 FAIL / 95 REFLEX / 10 WARN` 是跨源码、页面状态和视口的原始计数，不是独立产品缺陷数，也不能用“命令退出 0”替代验收。

## 2. 改进后的主要流程

用户进入 All work threads，先扫描名称和工作状态，再进入文档或现有终端。归档、恢复、删除通过明确的次级入口执行。文档在空间足够时与列表并排显示，空间不足时占据内容区，并可返回原列表位置。初次加载失败时提供清楚的错误原因和恢复操作。

界面继续使用现有字号、语义色与 8/12/16px 圆角。Sidebar 保持独立滚动与固定导航/Settings；Workspace 继续采用 40px 标题栏、32px 标签及工具栏、28px 紧凑控件。

## 3. 分批实施

每批为独立可验证、可回滚的提交。推荐顺序 A → B → C → D → E → F。A 与 D 不依赖布局改造；B/C 涉及浏览和编辑体验，需连续验收。

### A. 首次加载失败的恢复入口（R1，P1）

**目标行为**

- 初次查询仍在请求或重试时显示 loading；重试耗尽且没有快照时进入错误页。
- 错误页使用明确标题“Could not open SuperThread”，提供可选择的错误说明和 Reload 操作，并保留窗口拖动区域及 no-drag 按钮。通用错误边界还承接其他渲染异常，标题不能把所有异常都描述成快照读取失败。
- 将错误判断放在空数据 loading 分支之前，复用现有 EmergencyErrorBoundary，不为本次修复引入新的 IPC 或持久化状态。
- 现有快照可用时发生后台刷新失败，也需验证既有行为；本批不顺带扩展离线缓存策略。

**影响文件**：`src/renderer/src/features/workspace/WorkspaceApp.tsx`、`src/renderer/src/app/AppKernel.tsx`、错误页样式；行为说明更新到 `docs/mvp.md`。

**验收**：故障注入后，初次请求加既有一次重试均失败时，启动动画结束并出现错误及 Reload；恢复测试 handler 后 Reload 能进入正常界面。正常启动不闪出错误页。浅深色、880×560 下错误可复制、按钮可键盘触达，窗口仍可拖动。

**验证方式**：真实 Electron 故障注入，记录实际尝试次数和最终 DOM 状态，不能仅检查 JSX 条件顺序。

### B. 线程列表与自适应文档视图（R2/R3，P1/P2）

**空间规则**

以线程页面实际内容区宽度 W 决策，包含 Sidebar 收起、拖宽或拖窄带来的变化，避免单独使用窗口宽度断点。

| 条件 | 布局目标 |
| --- | --- |
| 文档关闭 | 列表使用可用内容宽度，保留当前搜索和状态筛选 |
| 文档打开且 W ≥ 960px | 列表/文档并排；列表宽度建议 `clamp(360px, 38%, 420px)`，文档取得剩余空间 |
| 文档打开且 W < 960px | 内容区只展示文档；提供可见的 Back to list，Sidebar 保持可用 |

960px 是首轮建议断点，不是现有事实。实施时以 360px 列表加可编辑文档的实际表现确认；不得让菜单按钮或正文溢出来维持断点。

**列表动作**

- 点击名称/行主体继续打开文档。保留可见的 Doc 入口，沿用现有点击习惯。
- 有 `firstTerminalTarget` 时，将窗口图标改为有文字的 Terminal 操作，继续打开当前算法选定的终端。没有终端时不再显示第二个去往文档的窗口图标。
- Archive、Delete 收入始终可触达的 More 菜单；Archived 列表保留清楚的 Restore 入口。保留原确认、busy 状态和“有 workspace 不可删除”的规则及原因。
- 菜单支持键盘打开、方向键或标准菜单导航、Escape 关闭与焦点恢复。不能仅在鼠标 hover 时显示唯一入口。
- 紧凑列表采用名称、元信息与动作的稳定结构。无搜索摘要时，单行条目的目标高为 64–80px；有摘要允许增加高度，仍限制动作区不单独多次折行。

**状态保留**

- 返回列表后保留 query、Active/Archived、滚动位置和当前条目。
- 跨断点调整尺寸时复用同一个编辑器和文档状态，不因宽窄切换丢草稿、重置光标或触发保存到错误线程。
- 宽屏并排时列表和文档可分别滚动；窄屏文档显示时，隐藏列表不得留在 Tab 顺序或辅助技术导航中。Back/Escape 后恢复到打开文档的条目，条目不存在时回到搜索框。
- 作为非模态内容详情处理，不因窄屏自动加全窗口 focus trap。

**影响文件**：`WorkThreadList.tsx`、`globals.css`，必要时增加 renderer 内的布局辅助模块和局部菜单组件。复用既有 store/自动保存；无新增持久化字段。新菜单如使用不同 class，需检查 `use-native-pane-layout.ts` 的原生视图遮挡识别。

**验收**：880×560 下不再出现约256px的双栏列表；1320×840、240px侧栏下可以并排浏览。184/240/340px侧栏与收起状态之间切换，所有动作和返回入口可用。长中英文名称、搜索摘要、无workspace、workspace无终端、有终端、Archived 均有明确入口。

### C. 压缩文档 chrome，增加阅读与编辑空间（R4，P2）

**布局目标**

- 内容详情使用一行紧凑标题栏，目标 40px；名称为16px，保存状态与关闭/返回保持可见。独立 Doc 页面使用相同信息层级并保留原生交通灯安全区。
- Document/Todos 切换占一行，目标32px。正常年龄并入这行的辅助信息，完整创建时间通过现有提示提供。
- 提醒与强提醒仍位于标题下方，允许自然换行，保持图标/文字和语义色。提示较长时可用披露展示完整建议，但不能仅靠颜色表达状态。
- “Document · Markdown”退出常驻副标题；格式信息如仍有需要，放入可获取的辅助说明。保持保存中、失败、Retry save 与本地草稿恢复反馈。
- 保持正文16px/1.75、阅读区最大840px；通过减少 chrome 与重复留白获得空间。

**影响文件**：`WorkThreadDocument.tsx`、`WorkThreadAge.tsx`、`globals.css`。继续消费既有 `workThreadAge` 计算结果，不修改提醒阈值或年龄算法。

**验收**：正常年龄、无保存错误时，从文档区域顶部到编辑器可视区域顶部不超过96px。该指标不含用户文档本身的标题边距；长提醒或错误信息允许增加高度。880×560仍能编辑正文、切换Todos及关闭/返回；普通、提醒、强提醒和保存失败均有截图。关闭、切换线程和调整窗口不丢最后输入。

### D. 输入边界与交互状态（R5，P2）

**实现方向**

- 新增浅深色 `--input-border`，只用于输入区域，保持列表/面板弱边框的现有层次。按实际周围背景测量后定值，不全局加深 `--border`。
- 搜索框把边界和焦点留在 `.work-thread-search` 外层，内部 input 仍无重复边框；普通字段复用 `.field`。
- 输入区域默认可识别边界至少3:1；focus-visible 指示至少3:1且立即出现；普通文字至少4.5:1。只把默认可操作控件纳入此边界验收，禁用控件单独评价。
- 定义可观察的 hover、active、focus-visible、disabled、busy、invalid 状态。disabled 通过填充/文字/光标及真实禁用行为表达，避免只有透明度。
- 检查 `.field` 的 `outline: 0` 与后续 `:focus` 覆盖，统一明确的键盘焦点指示。当前截图检查仅覆盖少量 Tab 目标，不能直接认定所有字段已有充分焦点反馈。
- 错误状态继续包含文字；加载和保存保持已有防重复提交行为。

**影响文件**：`globals.css`；需要字段状态类时局部修改 `Modal.tsx`、`SettingsDialog.tsx` 等现有控件消费者。不改表单校验或提交契约。

**验收**：搜索、Settings Markdown/数值输入、新建线程输入在浅深色的默认/焦点/禁用/错误状态均检查。Tab和Shift+Tab可观察当前焦点；hover不影响焦点环；状态变化不改变控件尺寸。对比度记录测量对象、前景/边界、背景和结果，避免只记录工具汇总。

### E. Workspace 概览的信息排序（R6，P2）

- 名称为第一层；项目与设备是稳定上下文字段；线程归属与分支是次级字段。用独立字段和间距组织，替代长中点串。
- 默认保留“本地运行数”与“远程连接数”的不同含义。有值时显示对应计数；全部为零时显示明确的 No running terminals，不将它表述为设备离线或异常。
- 统计摘要仍保留完整汇总。长线程名和路径省略时提供完整提示；窄窗口中先压缩次级信息，不让固定计数胶囊抢走全部宽度。
- 保留 workspace creating/error 状态，不只显示ready样例；整行仍可点击且有键盘焦点。

**影响文件**：`WorkspaceList.tsx`、`globals.css`。继续复用 `selection.ts` 的统计结果，不改变运行状态检测、远程采样或连接定义。

**验收**：0/多终端、本地/远程、Standalone/线程归属、长名称、creating/error、空列表均检查。880×560能辨识名称及设备；运行/连接信息与原算法一致，不新增远程探测。

### F. 动效与样式收尾（R7，P3）

- 布局宽度切换一步完成；视觉过渡仅使用 opacity/transform，并保留 reduced-motion。无需为细微动效增加复杂布局框架。
- 同步移除关闭清理对 `transitionend.propertyName === "width"` 的依赖，校准320ms fallback。关闭时隐藏区域立即 inert，编辑器清理与自动保存保持正确。
- 将标签关闭悬停、弹窗遮罩、轻阴影的三个颜色字面值提取到主题 token。
- 修改触及区域时复用已有间距 token；6px等已写入桌面规范的紧凑间距保留，不为消除告警全量重排CSS。
- 异常页 eyebrow 已在A中处理；不再作为独立设计任务重复统计。

**影响文件**：`WorkThreadList.tsx`、`globals.css`。本批依赖B最终布局；若width动画已在B中去除，本批只补剩余项。

**验收**：无width/height/top/left动画；正常与reduced-motion模式下反复开关、切换线程、关闭时仍在保存均正确。检查构建产物及截图，不只搜索CSS关键字。

## 5. 实施边界与文档同步

计划以现有 WorkThread、Workspace、Session 等已实现对象为基础，不新增业务实体。主要变动在 renderer；main/preload/shared 的文件系统、Git、SSH、PTY所有权与窄桥接保持原边界。

- 当前只新增本方案文档；实施文件列表是后续变更范围，不代表已执行。
- 行为变更随对应批次更新 `docs/mvp.md`：首次失败恢复、列表入口、窄屏文档返回、正常年龄信息的位置及概览状态文案。
- 尺寸、断点、输入token、控件反馈随对应批次更新 `docs/mac-native-ui-framework.md` 第15节；文档紧凑标题栏作为明确例外，不模糊修改所有页面76px头部规则。
- README只更新用户可见路径发生变化的部分。无数据迁移、无新增生产依赖、无后端任务。

## 6. 验证矩阵与完成条件

| 维度 | 必检样例 |
